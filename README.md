# Бот повторяющихся и приватных сообщений

Telegram-бот на `python-telegram-bot` (webhook-режим, деплой на Render).

## Что умеет

- **Повторяющиеся сообщения** — текст или медиа (фото, видео, стикеры,
  голосовые, кружки, файлы), с заданным числом повторений и интервалом.
- **Форматирование текста** — сохраняет форматирование, применённое через
  сам Telegram (жирный/курсив и т.д. через кнопки в приложении), а также
  понимает HTML-теги, напечатанные вручную (`<b>`, `<i>` и т.п.).
- **Эмодзи** — работают без специальной настройки, это обычные символы
  внутри текста.
- **Приватные ("эфемерные") сообщения** — видны только одному человеку;
  никто другой в группе их не видит. Эфемерными сделаны:
  - сами статусные ответы бота (`Принято...`, `/list`, `/cancel` и т.д.)
  - команды в группах (сама команда, которую вводит пользователь, тоже
    скрыта от остальных — не только ответ бота)
  - сообщения от `/whisper`, включая медиа
- **Автоматическое сообщение об ошибке** — если что-то не получилось
  обработать, автор команды получает понятное эфемерное уведомление,
  а не тишину.

Эфемерность реализована через сравнительно новую функцию Telegram Bot API
(`ephemeral_message_parameters`, Bot API 10.2–10.3, июль–август 2026).
Библиотека `python-telegram-bot` её пока не поддерживает напрямую, поэтому
такие запросы отправляются "сырыми" HTTP-вызовами к Bot API в обход
методов библиотеки (см. `safe_api_request` в коде). Если по какой-то
причине эфемерная отправка не пройдёт — бот автоматически отправит
обычное сообщение и удалит его через минуту, чтобы поведение всё равно
оставалось приватным.

## Команды

| Команда | Что делает |
|---|---|
| `/start` | Приветствие и краткая справка |
| `/repeat количество интервал` + текст на второй строке | Запланировать повторение текста |
| `/repeat количество интервал` (ответом на фото/видео/стикер/голосовое/кружок/файл) | Запланировать повторение медиа |
| `/list` | Показать активные повторения в этом чате |
| `/cancel номер` | Отменить повторение по номеру задачи |
| `/whisper @username текст` | Приватное сообщение указанному пользователю |
| `/whisper текст` (ответом на чьё-то сообщение) | То же самое, без юзернейма |
| `/whisper` + медиа | Можно вместо текста (или вместе с ним) приложить фото/видео/стикер — тоже станет приватным |

**Формат `/repeat` специально в две строки** — это позволяет надёжно
отделить служебные числа (количество и интервал) от самого текста
сообщения, даже если в тексте есть форматирование или цифры.

Пример:
```
/repeat 10 86400
<b>Ежедневный бонус!</b> Забери его 🎁
```

## Переменные окружения (Render → Settings → Environment)

| Переменная | Что это | Где взять |
|---|---|---|
| `BOT_TOKEN` | Токен бота | [@BotFather](https://t.me/BotFather) |
| `WEBHOOK_HOST` | Публичный адрес сервиса, вида `https://имя-сервиса.onrender.com` | Отображается на странице сервиса в Render (без пробелов и переносов строк!) |
| `WEBHOOK_SECRET` | Произвольная случайная строка для защиты вебхука | Придумать самому |
| `PYTHON_VERSION` | Версия Python для сборки | Например, `3.11.9` |
| `STARTUP_DELAY_SECONDS` | (необязательно) Пауза перед стартом в секундах, по умолчанию 10 | Обычно не требуется менять |

⚠️ **`WEBHOOK_HOST` должен начинаться с `https://` и не содержать
случайных пробелов/переносов строк** — при вставке в поле на Render
многострочные текстовые поля иногда добавляют невидимый перенос строки,
из-за которого Telegram возвращает ошибку `Bad webhook`.

## Деплой

1. Создать бота через @BotFather, получить `BOT_TOKEN`.
2. Загрузить `bot.py` и `requirements.txt` в GitHub-репозиторий.
3. На Render: New → Web Service → подключить репозиторий.
4. Build command: `pip install -r requirements.txt`
   Start command: `python bot.py`
5. Задать переменные окружения (см. таблицу выше).
6. После первого деплоя скопировать реальный адрес сервиса в
   `WEBHOOK_HOST`, если он ещё не совпадает, и передеплоить.
7. Через BotFather выполнить `/deletecommands` для этого бота (если
   команды задавались вручную раньше) — иначе будет конфликтовать со
   списком команд, который бот сам регистрирует при каждом старте
   (отдельно для личных чатов и для групп, чтобы эфемерность в группах
   не терялась).

## Ограничения

- Стикеры и видео-кружки не поддерживают подписи (ограничение самого
  Telegram, не бота).
- `/whisper @username` работает только если у человека есть публичный
  юзернейм и бот уже "видел" его сообщения в этом чате раньше. Если не
  сработает — используйте вариант с ответом (reply) на его сообщение,
  он работает всегда.
- Раз бот работает через webhook и "спит" между событиями (не требует
  UptimeRobot) — первый ответ после длительного простоя может прийти с
  задержкой 30–60 секунд, пока сервис "просыпается".
- Активные повторения хранятся в памяти процесса — при перезапуске
  сервиса (например, при новом деплое) все текущие повторения сбрасываются.
