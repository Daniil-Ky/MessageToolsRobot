# Бот повторяющихся, приватных и групповых сообщений

Telegram-бот на `python-telegram-bot` (webhook-режим, деплой на Render).

## Что умеет

- **Повторяющиеся сообщения** — текст или медиа (фото, видео, стикеры,
  голосовые, кружки, файлы), с заданным числом повторений и интервалом.
- **Форматирование текста** — сохраняет форматирование, применённое через
  сам Telegram (жирный/курсив и т.д. через кнопки в приложении), а также
  понимает HTML-теги, напечатанные вручную (`<b>`, `<i>` и т.п.).
- **Эмодзи** — работают без специальной настройки, это обычные символы
  внутри текста.
- **Приватные ("эфемерные") сообщения** — видны только одному человеку;
  никто другой в группе их не видит. Эфемерными сделаны:
  - все статусные ответы бота (`Принято...`, `/list`, `/cancel`, `/id` и т.д.)
  - сами команды в группах (`/start`, `/repeat`, `/list`, `/cancel`,
    `/whisper`, `/id`, `/send` — их ввод тоже скрыт от остальных)
  - сообщения от `/whisper`, включая медиа
- **`/id`** — узнать свой Telegram ID, либо ID другого человека (ответом
  на его сообщение). Всегда эфемерно.
- **`/convene` + `/send`** — публичное сообщение с уведомляющими
  упоминаниями нескольких выбранных людей. Получателей можно выбирать
  кнопкой или добавлять по Telegram ID (подробности ниже).
- **`/broadcast` + `/referrals`** — админские функции: рассылка всем
  пользователям бота и реферальные ссылки со статистикой (подробности
  ниже). Доступны только `ADMIN_ID`.
- **Автоматическое сообщение об ошибке** — если что-то не получилось
  обработать, автор команды получает понятное эфемерное уведомление,
  а не тишину.

Эфемерность реализована через сравнительно новую функцию Telegram Bot API
(`ephemeral_message_parameters`, Bot API 10.2–10.3, июль–август 2026).
Библиотека `python-telegram-bot` её пока не поддерживает напрямую, поэтому
такие запросы отправляются "сырыми" HTTP-вызовами к Bot API в обход
методов библиотеки (см. `safe_api_request` в коде). Если по какой-то
причине эфемерная отправка не пройдёт — бот автоматически отправит
обычное сообщение и удалит его через минуту, чтобы поведение всё равно
оставалось приватным. Все обращения к Bot API дополнительно защищены от
временного флуд-контроля (`retry_on_flood`, `safe_api_request` с
обработкой кода 429).

## Команды

| Команда | Где | Что делает |
|---|---|---|
| `/start` | везде | Приветствие, краткая справка, показывает ваш ID, запоминает вас как пользователя бота |
| `/repeat количество интервал` + текст на второй строке | везде | Запланировать повторение текста |
| `/repeat количество интервал` (ответом на медиа) | везде | Запланировать повторение фото/видео/стикера/голосового/кружка/файла |
| `/list` | везде | Показать активные повторения в этом чате |
| `/cancel номер` | везде | Отменить повторение по номеру задачи |
| `/whisper @username текст` | везде | Приватное сообщение указанному пользователю (не всегда находит) |
| `/whisper ID текст` | везде | То же самое, но по числовому ID — самый надёжный способ |
| `/whisper текст` (ответом на чьё-то сообщение) | везде | То же самое, работает всегда |
| `/whisper` + медиа | везде | Можно вместо текста (или вместе с ним) приложить фото/видео/стикер |
| `/id` | везде | Свой ID, либо ID другого человека (ответом на его сообщение) |
| `/convene Текст` | **только в личке с ботом** | Выбрать получателей для группового сообщения — кнопкой или по Telegram ID (см. ниже) |
| `/send` | **только в группе** | Отправить туда сообщение, подготовленное через `/convene` |
| `/broadcast` | только `ADMIN_ID` | Разослать сообщение всем пользователям бота |
| `/referrals` | только `ADMIN_ID` | Меню реферальных ссылок |

### Формат `/repeat`

Числа (количество и интервал) — на первой строке, текст — на второй.
Это нужно, чтобы надёжно отделить служебные числа от самого текста, даже
если в нём есть форматирование или собственные цифры:
```
/repeat 10 86400
<b>Ежедневный бонус!</b> Забери его 🎁
```

### `/convene` + `/send` — как позвать несколько человек

Telegram разрешает боту показывать кнопку выбора людей **только в личных
чатах** — в группах она физически не работает (официальное ограничение
Bot API). Поэтому процесс разделён на два шага:

1. **В личке с ботом:** `/convene Общий сбор сегодня в 19:00!` — команда
   и текст **одной строкой** (перенос строки ломает эфемерность команды
   на уровне самого Telegram, поэтому лучше избегать).
2. Появятся кнопки **«Добавить получателей»** и **«Готово»**. Жмите
   «Добавить» сколько угодно раз (до 10 человек за раз — жёсткий лимит
   самого Telegram на одно нажатие), список накапливается.

   **Альтернативный способ** — добавить человека по его Telegram ID:
   ответите (reply) на любое сообщение бота в этом чате числом
   (5–12 цифр) — и пользователь с этим ID добавится в список.
   Бот ответит подтверждением: «Добавлен пользователь с ID XXX. Сейчас
   выбрано: N чел.». Если ID уже в списке — бот сообщит об этом. Если
   число цифр меньше 5 или больше 12 — сообщение просто игнорируется
   (это не похоже на Telegram ID).

   Когда выбрали всех — жмите «Готово». Черновик сохраняется на 30
   минут.
3. **В нужной группе** напишите `/send` — бот отправит туда одно
   сообщение с текстом и упоминаниями всех выбранных.

Упоминания оформлены как кликабельные эмодзи (разные для каждого
человека, по возможности без повторов в одном сообщении), а не как текст
юзернейма — но именно они присылают адресату уведомление:
```html
<a href="tg://user?id=123456789">😎</a>
```
Ссылка `tg://user?id=...` выбрана намеренно вместо `https://t.me/username`
— только первая присылает уведомление и работает даже без юзернейма у
человека; обычная веб-ссылка на профиль уведомление не отправляет.

`/convene` не показывается в списке команд для групп (он там всё равно
не сработает) — только в личных чатах.

### `/broadcast` и `/referrals` — админские функции

Работают точно так же, как и в боте-уведомителе (общая логика и общая
таблица в Supabase):

- **`/broadcast`** — бот спрашивает сообщение (кнопка «Отмена»), затем
  рассылает его (текст/фото/видео/голосовое — что угодно) всем, кто хоть
  раз писал `/start` любому из ваших ботов, использующих ту же таблицу
  `bot_users` с меткой `whisper`.
- **`/referrals`** — меню: создать/удалить реферальную ссылку, статистика
  по одной или по всем ссылкам. Ссылка выглядит как
  `https://t.me/имя_бота?start=ref_название`.

Всем, кто не `ADMIN_ID`, эти команды не отвечают вообще.

## Переменные окружения (Render → Settings → Environment)

| Переменная | Что это | Где взять |
|---|---|---|
| `BOT_TOKEN` | Токен бота | [@BotFather](https://t.me/BotFather) |
| `WEBHOOK_HOST` | Публичный адрес сервиса, вида `https://имя-сервиса.onrender.com` | Отображается на странице сервиса в Render (без пробелов и переносов строк!) |
| `WEBHOOK_SECRET` | Произвольная случайная строка для защиты вебхука | Придумать самому |
| `SUPABASE_URL` | Project URL проекта Supabase | Тот же, что у бота-уведомителя |
| `SUPABASE_KEY` | Secret key проекта Supabase | Тот же, что у бота-уведомителя |
| `ADMIN_ID` | Ваш Telegram ID | Узнать через `/id` в этом же боте |
| `PYTHON_VERSION` | Версия Python для сборки | `3.11.9` |
| `STARTUP_DELAY_SECONDS` | (необязательно) Пауза перед стартом в секундах, по умолчанию 10 | Обычно не требуется менять |

⚠️ **`WEBHOOK_HOST` должен начинаться с `https://` и не содержать
случайных пробелов/переносов строк** — при вставке в поле на Render
многострочные текстовые поля иногда добавляют невидимый перенос строки,
из-за которого Telegram возвращает ошибку `Bad webhook`.

## Деплой

1. Создать бота через @BotFather, получить `BOT_TOKEN`.
2. В Supabase создать три таблицы (`subscriptions`, `bot_users`,
   `referral_links`) — SQL см. в README бота-уведомителя, это общая база
   для обоих ботов.
3. Загрузить `bot.py` и `requirements.txt` в GitHub-репозиторий.
4. На Render: New → Web Service → подключить репозиторий.
5. Build command: `pip install -r requirements.txt`
   Start command: `python bot.py`
6. Задать переменные окружения (см. таблицу выше).
7. После первого деплоя сверить реальный адрес сервиса с `WEBHOOK_HOST`,
   если он отличается — поправить и передеплоить.
8. Через BotFather выполнить `/deletecommands` для этого бота, если
   команды задавались вручную раньше — иначе будет конфликтовать со
   списком команд, который бот сам регистрирует при каждом старте
   (отдельно для личных чатов и для групп, чтобы эфемерность в группах
   не терялась, а `/convene` не показывался там, где не работает;
   админские команды `/broadcast` и `/referrals` в списке команд вообще
   не публикуются).

## Ограничения

- Стикеры и видео-кружки не поддерживают подписи (ограничение самого
  Telegram, не бота).
- `/whisper @username` работает только если у человека есть публичный
  юзернейм и бот уже "видел" его сообщения в этом чате раньше. Надёжные
  альтернативы — `/whisper ID текст` или ответ (reply) на его сообщение.
- Эфемерные команды с переносом строки внутри сообщения перестают быть
  скрытыми от остальных в группе — судя по всему, это ограничение самого
  Telegram для этой очень новой функции, а не что-то, что можно
  исправить в коде бота. Поэтому там, где это важно (`/convene`), формат
  сделан однострочным.
- Добавление по Telegram ID в `/convene` работает только если ответ
  (reply) адресован сообщению бота — ответ на чужое сообщение число
  не активирует. ID должен состоять из 5–12 цифр, иначе игнорируется.
- Активные повторения и черновики `/convene` хранятся в памяти процесса
  — при перезапуске сервиса (например, при новом деплое) они сбрасываются.
  Список пользователей и реферальная статистика при этом не теряются —
  они в Supabase, а не в памяти.
- `/broadcast` рассылает с небольшой паузой между сообщениями (0.05 сек),
  чтобы не упереться в лимиты Telegram — при большой базе пользователей
  это может занять заметное время.
- Раз бот работает через webhook и "спит" между событиями (не требует
  UptimeRobot) — первый ответ после длительного простоя может прийти с
  задержкой 30–60 секунд, пока сервис "просыпается".
